# Transcript instructions

## File naming

- Format: `YYYY-MM-DD-lastname-lastname.md`, for example `2026-01-15-smith-jones.md`.
- Use the date of the session.
- Use the last names of the people in the session, two or three at most.
- Use lowercase kebab-case.
- If there is more than one transcript for the same day with the same people, add a number. The first file has no number, the second is `-2`, the third is `-3`, and so on.

## Preparing a transcript

- Keep the speaker labels, timestamps, and the order of the conversation.
- Keep each speaker's own voice and wording. Make light edits only, not a formal rewrite.
- Keep people's names as spoken, so related conversations can be found elsewhere.
- Use the correct spellings of product and tool names from the project documentation and code. If you are unsure of a word, mark it `[unclear]` instead of guessing.
- Write every line so that any participant would be comfortable reading it. Describe people, roles, and workflows in neutral, factual, respectful terms.
- Use professional language throughout.
- Present the speaker's reflections in a confident, constructive tone.
- Keep the focus on what the transcript is for: design decisions and their reasoning, stories, techniques, lessons, and action items.
- Describe outside companies and tools factually.
- When a passage is shortened or reworded, preserve any decision, fact, or action item it contained.
- Mark a cut with a short bracketed note such as `[removed]`.
- Never add content that was not said.
- Do not summarize.
- Report your changes to the reviewer in your reply, not inside the transcript file.
